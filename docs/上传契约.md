# 上传契约 v2：模块独立确认与发布

0.2.0 支持市场、行业、个股和报告独立上传、独立日期、独立确认。每个批次目录可仅包含一个模块，也可包含多个模块；某一模块失败不会阻止其他已确认模块发布。客户端必须升级至0.2.0以正确显示不同模块日期。

后台读取 BSDT_INBOX 配置的目录，默认仅 test-upload。每个批次目录使用新编号，目录名等于 batch_id。先完整上传结果文件，最后原子写入 manifest.json。已经发布的模块编号不可修改，更正要用新的批次编号与更大的 revision。

```json
{
  "schema_version": 2,
  "batch_id": "stocks-20261012-v2",
  "modules": {
    "stocks": {
      "as_of": "2026-10-12",
      "revision": 2,
      "generated_at": "2026-10-12T17:00:00+08:00",
      "sample": false,
      "source": "上游实际来源",
      "complete": true,
      "confirmed": true,
      "confirmed_by": "实际确认人",
      "file": {"name": "stocks.csv", "sha256": "实际文件字节SHA256"}
    }
  }
}
```

## 日期与版本

- as_of：模块内容实际数据日期，必须是ISO日期。
- revision：同一模块、同一数据日期的正整数版本号，由上游约定并提供。不同生产者必须共同协调版本，不按目录名、文件时间或到达顺序猜测新旧。
- generated_at：上游结果生成时间，带时区。
- published_at / received_at：后台实际发布/接收时间，由后台记录。
- sample、source、complete、confirmed、confirmed_by：保留原来样例与人工确认要求。

版本按 `(as_of, revision)` 排序。较早日期或较低版本归档，同日同版本的新编号拒绝发布并提示增加版本；上游发布时间用于展示与追溯，不代替明确版本号。

## 结果字段

市场采用JSON对象：weather、summary可缺；metrics为数组，每项label必填，value可缺，真实0保留为0。行业、个股和报告采用JSON数组或UTF-8/BOM CSV。

- 行业：id必填文本且唯一；name、status、reason、next_check可缺。
- 个股：code必填文本且唯一，保留前导零；name、industry、status、reason、next_check可缺。
- 报告：id必填文本且唯一；title、content可缺。正文按纯文本展示。

缺失内容保存null，客户端显示“待补充”；不会编造值或用0替代缺失。错误标识、重复编号、坏JSON/CSV、校验失败仍会拒绝该模块。真实字段尚未拿到，上述为可用的通用接入契约；收到真实样例后在适配层做字段映射与核对。

## 接口与效率

- GET /api/overview：轻量模块版本、日期、待确认/失败摘要。ETag未变化返回304。
- GET /api/market：小体量市场数据。
- GET /api/industries、/api/stocks、/api/reports：page、page_size(1–100)、q、status，后台SQLite查询分页。报告列表不传正文，个股列表不传完整后续核对详情。
- GET /api/{模块}/{标识}：按需读取完整详情。version参数固定模块版本，避免列表与详情混用不同版本。
- GET /api/batches：接收记录，主要供设置页使用。
- GET /api/health：运行状态及扫描统计。

后台每15秒检查清单及文件的修改时间/大小/文件状态签名，未变化不读取内容；发生变化才读文件并校验SHA256。客户端默认30秒检查版本，接口支持条件刷新，缓存按后台地址、接口和模块版本隔离并限制数量。

## 旧版本兼容

schema_version=1的四模块整批清单仍可接入，保持整批完整确认要求。旧数据库已发布数据会迁移到新模块表，保留原表和原JSON；旧清单按日期与revision=1适配，同日更正须使用版本2清单。

0.1.x客户端共用一个日期，无法正确展示独立更新。后台仅在四模块仍是同一批次时提供旧snapshot；混合批次会明确提示升级。公司三台电脑应统一安装0.2.0。

## 演示命令

```powershell
.\.venv\Scripts\python.exe -m scripts.demo_modules --batch stocks-demo-v2 --modules stocks --date 2026-09-28 --revision 2 --csv --missing
```

可用 `--state pending` 或 incomplete 测试发布保护，`--count 5000` 构造大数据分页测试。只使用独立 test-upload，生成器拒绝覆盖已有批次。
